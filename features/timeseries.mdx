---
title: "Time-series Storage"
description: "Configure TimescaleDB or ClickHouse for monitor events and uptime history."
---

UptimeKit stores monitor events, status changes, and latency history in a time-series backend.

You can use either TimescaleDB or ClickHouse. Configure the backend with `TIMESERIES_BACKEND`.

## TimescaleDB

Use TimescaleDB when you want to store time-series data in PostgreSQL.

```bash
TIMESERIES_BACKEND=timescale
```

By default, TimescaleDB reuses the main application database from `DATABASE_URL`.

```bash
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/uptimekit
TIMESERIES_BACKEND=timescale
```

You can also store time-series data in a separate TimescaleDB database by setting `TIMESCALE_DATABASE_URL`.

```bash
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/uptimekit
TIMESERIES_BACKEND=timescale
TIMESCALE_DATABASE_URL=postgresql://postgres:postgres@localhost:5432/uptimekit_timeseries
```

The PostgreSQL database used for time-series data must have the TimescaleDB extension available.

## ClickHouse

Use ClickHouse when you want a separate high-throughput time-series database.

```bash
TIMESERIES_BACKEND=clickhouse
CLICKHOUSE_URL=http://localhost:8123
CLICKHOUSE_USER=default
CLICKHOUSE_PASSWORD=
```

Set these environment variables for each app that reads or writes monitor history.
